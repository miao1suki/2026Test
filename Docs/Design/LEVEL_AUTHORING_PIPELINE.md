# Level authoring and release pipeline

## Goal

Keep frequently changing or dirty development content separate from shipping content, while
allowing multiple designers and programmers to collaborate without editing the same Unity scene.
The directory and ownership model follows the level layout, not the operator's role.

## Source of truth

`Assets/_Project/Development/Levels/<LevelId>/Authoring` is the only canonical level source.
Each item has a stable ID and lives in one small ScriptableObject chunk:

```text
Development/Levels/LV001/
  Authoring/
    LV001_AuthoringDefinition.asset
    LV001_Layout.asset
    Pieces/
      Piece_01/
        Front/
          Geometry.asset
          Traversal.asset
        Right/...
        Back/...
        Left/...
      Piece_02/...
  Preview/Scenes/       generated 2D/3D authoring views
  Sandbox/              disposable local experiments

Release/Levels/LV001/
  Scenes/
    LV001_Main.unity
    LV001_GeneratedMap3D.unity
  Data/
```

- `Geometry.asset` owns grid map items.
- `Traversal.asset` owns ropes, ladders and rope platforms.
- A 2D piece, the total 2D layout and the folded 3D map are projections of the same records.
- Editing a generated preview object writes its transform and type-specific values back to its
  source chunk. Deleting through its proxy inspector removes the source record.
- Directly created rope, ladder, platform or grid objects must be **adopted** into the selected
  chunk through the pipeline window; leaving a loose object in a preview is not persistence.

## Editor workflow

Open `Tools > 2026Test > 关卡创作管线 > 打开管线窗口`.

1. Initialize the level structure if it does not exist.
2. Select a Piece and generate its small-piece preview. This scene contains the standard
   `CubeMapPieceAuthoring` face roots, so the existing grid-map Scene UI can place, rotate, snap and
   overlap items using the correct fine grid.
3. Select the matching Geometry chunk, create a grid item, then adopt it. Anchor, rotation, snap,
   overlap and unsnapped position are preserved in the canonical record.
4. Generate the total-2D or folded-3D preview for combined inspection.
5. Move an existing generated object; mouse release writes it back automatically. The inspector
   also exposes explicit save and source-delete operations.
6. To add an item with an existing map/rope/ladder tool, select the correct chunk, create/select
   the object, and click **把选中对象收编到当前数据块**.
7. Validate and publish. Publishing rebuilds `Release/.../LV001_GeneratedMap3D.unity`; Release does
   not reference Development chunks or preview proxies.

`LV001_Layout.asset` only stores face dimensions and grid resolution. Piece count is stored by the
new authoring definition, and no canonical data depends on a legacy `.unity` scene path.

## Multi-person Git ownership

Assign work by data chunk, for example `LV001 / Piece_02 / Right / Traversal`. Two people may work
on the same level at once if they own different chunk assets. Avoid simultaneous edits to the same
`.asset`; coordinate or hand off first when that is unavoidable.

Workers create branches and only pull, commit and push their own branch. They do not merge. The
integrator validates all chunks, regenerates previews/Release output and performs the merge.
Generated previews and Release files should normally be regenerated by the integrator, so workers
do not compete over generated scene YAML.

## Build boundary

The release main scene loads the generated map scene additively. Both Release scenes must be in
Build Settings. An enabled scene under `Assets/_Project/Development` causes a build error. Shared
runtime prefabs, materials and code remain under `Content` and `Code`; only level instances and
generated scene composition cross this boundary.

## Removed legacy entry points

`Assets/_Project/Scenes/Levels/LV001` and the old path-based workspace were removed after the clean
framework reset. Do not recreate or edit those scenes. Every persistent level object must live in a
chunk under `Development/Levels/<LevelId>/Authoring`; Piece, total-2D and folded-3D scenes are
generated projections and may be rebuilt at any time.
